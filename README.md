## Backend

### Необходимый инструментарий

Требуется Python 3.14+ и PostgreSQL 13+.

### Подготовка базы данных

Подключиться к PostgreSQL под пользователем `postgres` (через DBeaver, pgAdmin или psql) и выполнить:

```sql
CREATE USER onboarding_app_admin WITH PASSWORD 'TST5399112';
CREATE DATABASE onboarding_db OWNER onboarding_app_admin;
```

### Установка библиотек и запуск

```bash
cd backend
python -m venv venv
venv\Scripts\activate           # Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # Linux/macOS: cp .env.example .env
alembic upgrade head            # создать или обновить таблицы в базе
uvicorn main:app --reload
```

Проверка работы (GET-запрос, возвращает JSON ответ, если база недоступна - ошибка 500): http://127.0.0.1:8000/testconnect/
Документация API: http://127.0.0.1:8000/docs

### Применение миграций

После изменения моделей в `backend/models`:

```bash
alembic revision --autogenerate -m "краткое описание изменений"
alembic upgrade head
```

Перед применением проверьте сгенерированный файл в `migrations/versions`.
После `git pull` выполните `alembic upgrade head`, чтобы получить изменения базы от других участников.

### Модель данных

| Таблица | Что хранит |
| --- | --- |
| `users` | Аккаунт компании: название, e-mail, хэш пароля, время согласия с условиями использования |
| `sites` | Сайты пользователя: базовый адрес (`base_url`, `origin`, `base_path`), данные сигнала подключения виджета, номер текущей публикации |
| `themes` | Настройки с экрана «Настройка вида»: цвета, шрифт, скругление, положение по умолчанию. Одна тема на сайт |
| `project_drafts` | Проект сайта целиком в JSONB (формат `schema: 4` из `src/model.js`) с номером ревизии |
| `publications` | Неизменяемые снимки опубликованных сценариев с номерами версий — их получает виджет |
| `events` | События виджета с версией конфигурации, временем события и временем получения сервером |

Основные решения:

- **Сценарии и шаги хранятся внутри JSON** черновика и публикаций, отдельных таблиц для них нет. Панель сохраняет проект целиком, поэтому на сервере он хранится в том же виде.
- **Ревизия черновика** увеличивается при каждом сохранении. Если проект изменили в другой вкладке, сохранение устаревшей версии отклоняется, и свежие изменения не теряются.
- **Публикации не изменяются** после создания. Посетитель, начавший тур, проходит его до конца по той версии, с которой начал, даже если вышла новая публикация.
- **Id сценариев и шагов** создаёт панель, сервер их не меняет. Уникальность проверяется в пределах сайта, а не глобально. Id сайта генерирует сервер (случайный UUID).
- **События уникальны по паре** `(site_id, event_id)`: повторная отправка того же события не искажает статистику.
- **Каскадное удаление:** пользователь → сайты → тема, черновик, публикации, события.
- **Правило именования** индексов и ограничений задано в `db.py`, чтобы будущие миграции могли надёжно их изменять.

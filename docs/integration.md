# Подключение сайта

## Текущий прототип

В конструкторе один подключённый демосайт и несколько независимых сценариев.
Черновики сохраняются в localStorage браузера; автоматической серверной публикации пока нет.
Старый черновик с одним туром переносится в «Основной сценарий».

1. Создайте сценарии, добавьте шаги и настройте компьютерные и мобильные цели.
2. Выберите способ запуска каждого сценария: приглашение справа внизу, клик по выбранному элементу или JavaScript.
3. Кнопка «Проверить триггеры» проверяет все включённые сценарии внутри окна сайта.
4. В разделе «Подключение сайта и экспорт» скачайте `onboarding.json`.
5. Разместите JSON на своём сайте и укажите его URL в этом разделе. Скопируйте сформированный тег `script` на все страницы сайта.

Атрибут `data-site-id` должен совпадать с `siteId` в JSON. `data-config-url` — адрес доступного JSON, а `data-editor-origin` — origin конструктора для связи с предпросмотром.
Если JSON размещён на другом домене, его сервер должен разрешать загрузку с домена сайта через CORS.
Для открытия сайта в конструкторе сервер сайта должен разрешать встраивание в iframe с домена конструктора.

Изменения черновика применяются на внешнем сайте после обновления JSON.
Публичный демосайт использует отдельный пример из `demo-source/onboarding.json`: приглашение знакомит со школой на четырёх страницах, а кнопка «Как заполнить заявку?» запускает второй сценарий.

## Запуск из своего кода

```js
await window.Onboarding.ready
await window.Onboarding.start('scenario-id')
window.Onboarding.stop()
```

Метод `start` возвращает `false`, если сценарий неизвестен, уже идёт обучение или не удалось загрузить конфигурацию.
`window.Onboarding.scenarios()` возвращает список доступных идентификаторов и названий.
Можно вызывать `start` после своего события: открытия кабинета, успешного действия или нажатия вашей кнопки.
Для кнопки, назначенной триггером через конструктор, виджет перехватывает клик и запускает обучение.

```js
window.addEventListener('onboarding:event', event => {
  console.log(event.detail.name, event.detail.scenarioId, event.detail.index)
})
```

События пока доступны только в браузере, серверной аналитики нет.
Один запуск имеет общий `runId` и глобальную нумерацию шагов.
На отдельном сайте прогресс хранится в sessionStorage текущей вкладки, а в конструкторе — в состоянии редактора.
«Далее» и «Назад» переходят на страницу соответствующего шага и продолжают тот же сценарий.
Данные форм при этом автоматически не отправляются.

## Подключение в будущей серверной версии

Сначала владелец добавляет URL сайта в кабинете. Сервер создаёт запись сайта и его идентификатор и выдаёт готовый тег скрипта.
После установки виджет запрашивает опубликованные сценарии по идентификатору сайта и отправляет сигнал подключения.
Кабинет показывает подтверждённое подключение; новые сценарии публикуются через сервер без ручного обновления JSON.
Само добавление скрипта не должно создавать случайный сайт в чужом кабинете: сайт заранее связан с аккаунтом владельца.

## Локальный запуск

В двух терминалах из папки проекта выполните `npm run dev` и `npm run demo`.
Конструктор: http://localhost:5173/, встроенный демосайт: http://localhost:4174/.
Проверки: `npm test` и `npm run build`.
